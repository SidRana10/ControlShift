# Grounded-answer evaluation (offline)

_Generated by `eval/answer_eval.py` from `eval/answer_results.json`. **No language model was called to produce any number below.** Gold labels are AI-curated and source-checked, **not human-reviewed**._

## 1. What this evaluates, and what it does not

Three assurance levels are kept separate:

| Level | Question answered | Who decides |
|---|---|---|
| Structural | Do cited chunk / crosswalk-row ids exist, belong to the evidence bundle and match stored provenance? | code |
| Deterministic factual | Do mappings equal official crosswalk rows? Are versions right? Are conflicts preserved? Is abstention right? Is removal wording supported? | code, against SQLite + gold |
| Semantic faithfulness | Is the prose actually supported by the cited text? Is it complete and clear? | **a human reviewer (pending)** |

Passing structural and deterministic checks does **not** show that an answer is faithful. Offline mode measures (a) the evidence the pipeline hands to a model and (b) whether the checker itself works. It says nothing about Gemini's accuracy.

## 2. Gold dataset

- 20 questions from `eval/answer_questions.jsonl` (sha256 `664bdd74c0dccc3a...`).
- Expectations come from the stored NIST text and official crosswalk rows: quoted facts are verified as substrings of stored chunks, crosswalk row sets are read from SQLite, conflict/new/unmapped claims are re-verified against the rows, and 'absent' topics are verified to occur nowhere in the corpus.
- **Not human-reviewed** (`human_reviewed: false` on every record). No generated answer was used as ground truth.
- `abstention` = a valid question whose evidence cannot support an answer (unknown control; topic absent from the corpus, justified by several concept terms having zero occurrences rather than one missing keyword). `invalid_input` = a blank/invalid request: the API returns HTTP 422 before any retrieval or generation, so it is not an abstention and is never sent to a model.

## 6. Live-provider mode

Not run. Live mode is disabled by default; it needs `--live`, `RUN_LIVE_LLM_EVAL=1` and Gemini credentials, makes at most `--live-limit` requests and never retries a failed generation. No live answer accuracy is reported here.

## 7. Limitations

- 20 questions; one gold author (an AI); no human review of labels or answers.
- Evidence-stage results depend on the BM25 retrieval used here; hybrid/rerank evidence may differ. The gold file was written by the same assistant that built the pipeline, so high pass rates are regression checks, not evidence of robustness on unseen questions.
- The removal-wording rule is a keyword heuristic; synonyms are missed and benign uses can be flagged.
- Conflict and mapping checks verify structure (ids, rows, pairs), not whether the prose describes them well.
- The self-test uses defects we thought of; real model failure modes may be missed.
